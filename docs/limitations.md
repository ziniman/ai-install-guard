# What it is not

- **Not a proof of safety.** Static analysis raises the bar and makes every capability visible; a determined attacker can still evade it.
- **Install it first.** It judges only mods that load after it: folders given with `--plugin-dir` load first, and installed plugins load in the order your settings list them. For a company, the strongest setup is deploying it through managed settings so it loads first.
- **No per-plugin block for classic shell hooks.** Claude Code runs them outside mods, so the guard cannot stop one once its plugin is installed. Its protection is the scan before install: a plugin you reject is never installed.
- **The `/plugin` menu installs without a scan.** A plugin picked from the menu is installed as Claude Code fetches it; the guard says so when the menu opens. Its mod is then kept from loading until you approve its files, but its skills, classic hooks and MCP servers are not held by that gate, and the skill gate leaves a plugin's skills to its install; the check at the start of the next session scans it. To scan before anything lands, install with `/plugin install <name>@<marketplace>`.
- **A held skill's files can still be read.** The guard replaces a held skill's instructions with a note telling Claude not to read its files to follow them, but it does not stop Claude's Read tool from opening them.
- **A skill's inline commands run before the guard sees a skill it did not find.** The guard judges a skill before it runs when it finds it by name in the session's `.claude` folders or yours. One Claude Code finds elsewhere (a subagent's preload, a nested folder) is judged only as its instructions load, after its inline commands ran. What a skill's arguments and its inline commands add to its instructions is not scanned, only its files.
- **Claude's commands are read, not run.** The guard finds an install in a shell command however it is quoted or wrapped (`env`, `sudo`, `sh -c`, `eval`, a here-document), and holds a command it cannot read (one built while it runs, a script piped into a shell, inline code for another language) as Could not verify. It finds the files a command writes the same way, through the programs it knows; a program that writes into Claude's folders on its own, without being given the path (an installer script, a package run with `npx`), is not seen. A script file that installs something is not read; the mod loading and skill gates, and the check at the start of a session, are the backstop for that.
- **The check at the start of a session comes after the fact.** It runs once the session has started, so a plugin's classic hooks and MCP servers have already started by then; Turn off keeps them from the next session. The first check on a machine only names what was already on. It covers plugins: an MCP server or a hook added to a configuration or settings file outside Claude Code is not checked yet.
- **Between Install and the install itself** Claude Code fetches the plugin again. The guard checks the commit just before, and a commit is fixed content, but a marketplace that names a branch rather than a commit can move in that moment. The scan warns about such marketplaces.
